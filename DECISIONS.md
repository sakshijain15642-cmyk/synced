- Day 1: Chose FastAPI because it's async-friendly (needed for WebSockets later) and generates API docs automatically.
- Day 2: Used Docker Compose so the API and Postgres run identically on any machine. Containers talk by service name (db), not localhost.
- Day 3: Used SQLAlchemy 2.0 ORM + Alembic migrations instead of hand-written SQL, so schema changes are versioned and reproducible. Team membership is a separate table (many-to-many). Roles will be added in Week 6 via a migration.
- Day 4: Argon2 for password hashing (deliberately slow, salted automatically). Stateless JWT access tokens, 60 min expiry. Same error for unknown email and wrong password to avoid leaking which emails exist. Secret key lives in .env, never in Git.
- Day 5: Incidents are nested under teams (/teams/{id}/incidents) so ownership is explicit in the URL. Non-members get 404 rather than 403 so team ids can't be probed. Status/severity validated with Literal types at the API edge. List endpoint is newest-first with limit/offset pagination (limit capped at 100). Creating a team and its first membership happen in one transaction.
- Day 6: PATCH (partial update) instead of PUT, using exclude_unset to tell "not sent" from "sent as null". Every incident lookup checks BOTH team membership AND that the incident belongs to the URL's team, to prevent IDOR. Any team member can edit for now; roles (commander/responder/viewer) come in Week 6. Updates overwrite state, which Week 4 replaces with an append-only event log.
- Day 7: pytest with FastAPI TestClient against a real Postgres test database (not SQLite) so tests behave like production. Test DB name must end in "_test" or the suite refuses to run. Tables are truncated before every test for isolation. GitHub Actions runs the suite on every PR using a Postgres service container.
